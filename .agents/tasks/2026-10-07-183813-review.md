# Desktop novo fluxo — sub-rotas e componentes globais

A implementação entrega o novo fluxo desktop da Valora em quatro commits: sub-routing para `/ativos`, `/desempenho` e `/analise` com lazy-loading de todos os sub-componentes; telas Posições, Composição e Lançamentos dentro de `/ativos`; telas Rentabilidade, Proventos, Score e Alertas dentro de `/desempenho` e `/analise`; e redesign do `QuickTransactionModal` e `WalletMorphSelector`. Toda a estrutura parte de `AppShellNovo` com `SidebarNovo` collapsível e `TopBar` com seletor de carteira e sino.

**Watch for:**
- Sub-routing `/ativos → /ativos/posicoes` funciona (confirmed), mas existe uma `visao-geral` placeholder em `/desempenho` e `/analise` que nunca é alcançada pela navegação sem link explícito (likely).
- Quatro test files falham (37 testes) — confirmed pré-existentes na branch base `feature/VLR-REFINAMENTO-INTERFACE`; nenhuma regressão foi introduzida.
- `etf_us` está listada em `INTERNATIONAL_TYPES` no código de produção, mas os testes e a spec do produto pedem que fique fora (likely — os testes da suite de composição cobrem isso e estão failing por essa divergência desde antes da branch).
- `Filter` e `Export CSV` nos cabeçalhos de Posições e Lançamentos estão como botões sem handler (confirmed) — UI decorativa por ora.

**Verdict**: APPROVED

## High-level view

O sub-routing está correto: cada seção tem um shell com `<Outlet>` e o índice redireciona para a primeira sub-rota, eliminando a necessidade de qualquer redirect manual no navegador. O lazy-loading com `Suspense` é uniforme em todas as sub-rotas. `AppShellNovo` é o único ponto que instancia o `QuickTransactionModal`, o que evita múltiplos listeners de mutação.

Cada sub-tela busca seus próprios dados com hooks existentes (`usePositions`, `useLatestQuotes`, `usePerformance`, `useDividends`, `useAlerts`), sem criar cópias da lógica. A derivação `derivePositionRows → enrichPositionRows` é reutilizada em `AtivosPosicoes` e `AtivosComposicao`, e o mesmo `deriveComposition` alimenta o donut. O único cálculo duplicado é o bloco `valorInvestidoBRL` que aparece identicamente em `AtivosPosicoes` e `AtivosComposicao` — candidato a hook.

Os tokens visuais `bg-[#1A1A1A]`, `border-white/[0.08]`, `text-nf-green`, `text-nf-pink` e `text-nf-blue` estão presentes em todos os componentes novos, com consistência. `PanelCard` usa `bg-[#1B1B1B]` (não `#1A1A1A`) — diferença de 1 tom deliberada para cards versus fundo de página.

O `WalletMorphSelector` implementa fechar-ao-clicar-fora e Escape corretamente com limpeza do listener. O `QuickTransactionModal` valida quantidade, preço e sell-quantity-cap antes de chamar a API; o fluxo de erro retorna mensagem genérica para qualquer exceção não antecipada.

## Sub-routing e lazy-loading

Cada seção tem seu shell (`AtivosPage`, `DesempenhoPage`, `AnalisePage`) com `<Outlet>` e `SubTabBar`. O índice de cada seção é `<Navigate to="posicoes" replace />` (ou `rentabilidade`/`score`), então uma navegação direta para `/ativos` sempre cai em `/ativos/posicoes` sem flicker. Todos os componentes-folha são carregados com `React.lazy` + `Suspense` com fallback de loading. As rotas legadas (`/carteira`, `/patrimonio`, etc.) são mantidas intactas — nenhum path existente foi removido.

A `AppShellNovo` substitui o `AppShell` anterior como layout root. O switch entre mobile e desktop em `HomeRoute` e `IndexRoute` redireciona `/` para `/inicio` em desktop e `/carteira` em mobile, preservando comportamento anterior para usuários mobile.

## Duplicação de cálculo de custo médio

`AtivosPosicoes` e `AtivosComposicao` têm o mesmo `useMemo` que itera `positions` multiplicando `quantity × average_price × rate`:

```tsx
// aparece identicamente em ambos os arquivos
const valorInvestidoBRL = useMemo(() => {
  if (positions.length === 0) return null
  let total = 0
  for (const p of positions) {
    const qty = Number(p.quantity)
    const avgPrice = Number(p.average_price)
    const currency = p.asset?.currency ?? 'BRL'
    const rate = currency === 'USD' ? usdRate : 1
    total += qty * avgPrice * rate
  }
  return Number.isFinite(total) && total > 0 ? total : null
}, [positions, usdRate])
```

E também os cálculos de `ganhoCapitalBRL`, `proventos12mBRL` e `rentabilidadePct`. Isso não introduz bug hoje, mas é o tipo de duplicação que diverge silenciosamente quando a regra de câmbio muda.

## Botões decorativos em AtivosPosicoes

O cabeçalho do card de posições tem dois botões (`Filtrar` e `Exportar CSV`) sem `onClick`. O botão Exportar CSV em `AtivosLancamentos` tem implementação real. A inconsistência é: quem vê a tela Posições não consegue distinguir o que é funcional do que é placeholder.

## `console.warn` em AtivosLancamentos

O `ErrorBoundary` interno usa `console.warn('Chart error', e, i)` no `componentDidCatch`. Não é `console.error`, mas aparece no build em modo produção. O critério de "sem console.error críticos" está satisfeito; o warn é de baixo risco.

Os testes de composição esperam `ASSET_CLASS_LABEL.stock_br === 'Ações BR'` e `INTERNATIONAL_TYPES` sem `etf_us` — divergência que existe desde antes desta branch.
