- (event) PRD criado para o MVP do Valora usando documentação existente, protótipos HTML e decisão preliminar de Supabase como base.
- (decision by user) Rigor do produto: MVP para lançamento real.
- (decision by user) Arquitetura inicial: Next.js + Supabase direto no MVP.
- (decision by user) Escopo de ativos: todos os tipos previstos com adendos e priorização progressiva.
- (decision by user) Entrada da carteira: cadastro manual de posições e transações, com opção de importar CSV.
- (decision by user) Alertas entram no MVP como alertas internos simples.
- (decision by user) Dados externos: começar com seed/mock e plugar APIs depois.
- (decision by user) Tema visual oficial: dark-only por enquanto.
- (change by user) Mudança arquitetural: Vite em vez de Next.js para o frontend.
- (event) Iniciando Finalize: auditoria do memlog, reconciliação de inputs, reviewer gate, triage de questões abertas, polish, e close.
- (event) Reconciliação README completa: 5 gaps qualitativos identificados (tom aspiracional, dark como diferenciador, job emocional, uso mensal, escanabilidade).
- (event) Reconciliação VALORA_COMPILADO completa: 3 gaps críticos (posicionamento vs concorrentes, público B2B sub-representado, decisão arquitetural monolito vs microserviços ausente), 3 importantes (roadmap 3 fases, riscos, design system), 1 menor (tone of voice).
- (event) Reconciliação Protótipos HTML completa: 5 gaps (campo telefone, recuperação senha, tela detalhe ativo, grupos colapsáveis, métricas adicionais), 2 inconsistências (valora_score.html tema claro, versões duplicadas de estratégias).
- (event) Review de qualidade concluído: veredicto ADEQUATE. 1 finding crítico (3 questões bloqueiam arquitetura: consolidação protótipos, fórmula Bazin), 4 findings high/medium (mock data vs rastreabilidade, target user vs escopo MVP, conversão moeda fixa, WCAG adiado).
- (decision by user) Arquitetura confirmada: monolito modular (Vite + React + Supabase) em vez de microserviços no MVP.
- (decision by user) Telas: valora_ativo.html mantido no MVP, valora_score.html já está em dark, valora_estrategias.html e valora_estrategias (1).html têm conteúdo diferente - ambos devem ser considerados.
- (decision by user) Preço-Teto: MVP implementa apenas método Bazin (fórmula padrão: Dividendo anual / DY mínimo).
- (decision by user) Cadastro: adicionar campo telefone e funcionalidade de recuperação de senha.
- (decision by user) Cotação USD: usar API pública (AwesomeAPI ou similar) em vez de taxa fixa no MVP.
- (event) PRD atualizado com todas as decisões: FR-4 recuperação senha, FR-1 telefone, FR-26 detalhe ativo, arquitetura monolito confirmada, Preço-Teto apenas Bazin no MVP, cotação USD via API pública. FRs renumerados (1-28). Questões resolvidas movidas para §11 Decisões Arquiteturais.
- (event) Polish concluído: FR-18 corrigido para Bazin-only, UJs simplificadas, contradições de tema e escopo resolvidas.
- (event) PRD finalizado e marcado como status: final.
